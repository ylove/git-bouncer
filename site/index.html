Don't just git clone.
Let the bouncer check it first.

Malicious repos are now a routine way to attack developers: poisoned starter kits, fake take-home tests, look-alike accounts like micr0s0ft. git-bouncer checks a repo in a throwaway sandbox before any of it touches your laptop.

npm install -g git-bouncer

Then, instead of git clone <url>: bouncer clone <url> or git bouncer <url>

1 ID check

Before anything downloads: who published this? Look-alike owners, impersonated projects, brand-new accounts and repos named in active malware campaigns are caught on your machine, from public GitHub metadata.

2 Pat-down

The repo is cloned into a locked-down, throwaway container with none of your credentials. No capabilities, read-only filesystem, nothing mounted. Then it's checked for the techniques real campaigns use. None of its code is run.

3 Verdict

Clean? It asks before cloning to your machine, at the exact commit it checked, and installs only the dependency tree it verified. Not clean? It tells you what it found, in plain language, and deletes the sandbox.

What the pat-down looks for

  • Runs when you open the folder: VS Code tasks set to folderOpen, dev container commands that run on your host, AI-agent hooks and MCP servers.
  • Runs when you install: every install script npm would run, including binding.gyp builds and workspace scripts, plus .npmrc, .yarnrc and .pnpmfile.cjs tricks that work even with --ignore-scripts.
  • Poisoned dependencies: known-malicious packages (OSV), checksum mismatches against the lockfile, invalid registry signatures, typosquats, packages from outside the registry.
  • Hidden code: payloads pushed off-screen with whitespace, decode-then-execute, fake font files that are JavaScript, blockchain command-and-control, invisible Unicode and Trojan Source.
  • Git tricks: symlinks out of the repo, .git look-alike paths, case collisions, odd submodules. The clone itself happens in the sandbox.

What it can't do

A clean result means no known red flags, not "safe". Static checks can be evaded, brand-new malware isn't in the databases yet, and nothing is run, so behavior that only shows up at runtime isn't seen. git-bouncer shrinks the blast radius of your first contact with an unfamiliar repo. It doesn't replace your judgment. Read the threat model →

No Docker?

It works with Podman (free, open source, no account), and can offer to install it. It can also run the check in your own Google Cloud or AWS account (a throwaway GitHub Codespace option is coming soon).
